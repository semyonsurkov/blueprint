# blueprint

Локальная страница проекта, которая ставится в чужие репозитории командой `blueprint init`. Как
встроить её в проект, описано в разделе «Для агента» в `README.md`; этот файл про работу над самим
blueprint.

## Ограничения, которые нельзя нарушать

- Без сборки и npm: страница это ES-модули, которые браузер грузит как есть; библиотеки только с
  `esm.sh` по закреплённой версии и только там, где нужны (React и Excalidraw лениво в `schema.js`,
  marked и DOMPurify лениво в `markdown.js`).
- Версия библиотеки меняется только через `python3 scripts/deps.py update`: он держит `versions.json`
  и адреса `esm.sh` в `page/` согласованными и проверяет `peerDependencies`. Конфликт версий,
  о котором он сообщает, не обходится: решение за владельцем репозитория. Новый пакет сначала
  добавляется в `versions.json`, потом в код, и проверяется `blueprint vendor`: страница с локальной
  копией не должна делать ни одного запроса к `esm.sh`. Тяжёлый пакет, который нужен целиком,
  добавляется в `BUNDLED` в `bin/vendor.py`, необязательный динамический импорт в `SKIPPED_IMPORTS`.
- CLI и сервер на стандартной библиотеке Python 3.9+, все `read_text` и `write_text` с
  `encoding="utf-8"`.
- Свой кит `page/ui.css` на токенах, UI-библиотек нет. Новый контрол собирается из классов кита.
- Код инструмента живёт в `page/` и попадает в проект через `init` и `update`. В
  `template/mockups/` только то, чем владеет проект после установки: `wire.css`, `wire.js`,
  `screens.json`, экраны, `AGENTS.md` и заготовка `index.html`. Логику доски, комментариев и экранов в
  шаблон не класть: `update` до него не доходит.
- Сервер пишет только в схемы из конфига и `FEEDBACK.md` рядом с доской; любая новая запись
  проверяется по конфигу, по `Host` и `Origin` и пишется атомарно.

## Раскладка

`bin/blueprint` команды CLI, `bin/layout.py` поиск раскладки проекта, `bin/mockups.py` проверка
макетов. В `page/` один файл на ответственность, список с описанием в разделе «Как устроено»
`README.md`.

## Проверка изменений

Тестов нет. Изменение проверяется запуском:

1. `blueprint init --json` на временных проектах разной раскладки: пустой, монорепо с
   `apps/web/docs`, документация с `node_modules`, `--docs .`.
2. Страница в браузере на светлой и тёмной теме: каждая вкладка, переход по ссылке на `.md` из
   roadmap, доска макетов, режим комментария, отметка `[x]` в `FEEDBACK.md` с диска не затирается
   новым комментарием.
3. Сервер запросами: `/.env`, `/%2Eenv`, `/.ENV`, чужой `Host`, запись с чужим `Origin`,
   битое тело схемы.
4. `blueprint check` в заготовке макетов пишет «макеты в порядке».
5. `python3 scripts/deps.py check` выводит таблицу без строк с «!».

## Текст и коммиты

README и сообщения CLI на русском по `~/.agents/standards/writing-style.md`, коммиты по
`~/.agents/standards/commit.md` в Conventional Commits, без Co-Authored-By.
