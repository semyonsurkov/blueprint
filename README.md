## Возможности

- Схема архитектуры в Excalidraw на весь экран. Блоки двигаются и правятся мышью, а изменения сами сохраняются в `docs/architecture.excalidraw` проекта, так что схема живёт в git рядом с кодом и её видно в диффе.
- Документы к схеме открываются кнопкой в шапке боковой панелью поверх холста, например `docs/stack.md`. Подпись кнопки задаётся в конфиге, `Esc` закрывает панель.
- Доска каркасов экранов. Все экраны из папки макетов выложены на одну страницу по группам (десктоп, телефон). Доска двигается пробелом с мышью, как в Figma, и масштабируется колесом с Ctrl или ⌘. Режим «Оставить отзыв» превращает щелчок по любому элементу в заметку с номерной точкой, а все заметки видны в панели справа и сохраняются в `FEEDBACK.md` рядом с макетами.
- Документация проекта деревом: папка из конфига слева, документ справа, ссылки между документами открываются внутри страницы, схемы mermaid рисуются.
- Список ADR с номером, названием и статусом из заголовка каждого решения.
- Roadmap и инбокс идей из markdown. Документ можно сделать выпадающим блоком, раскрытым или свёрнутым по умолчанию: roadmap открыт, идеи под спойлером.
- Вкладки и файлы задаются одним `blueprint.json`. Страница не хранит своих данных, она показывает файлы проекта, поэтому правка в редакторе и правка на странице это одна и та же правка.
- Светлая и тёмная тема по системе с переключателем, скелетоны при загрузке без сдвигов шапки.
- Ни npm, ни сборки: сервер на стандартной библиотеке Python, браузер берёт React, Excalidraw, marked и mermaid с `esm.sh` по зафиксированным версиям.

## Установка

Нужен Python 3.9 или новее и браузер с доступом к `esm.sh`.

```bash
git clone https://github.com/semyonsurkov/blueprint.git
cd blueprint
./install.sh
```

`install.sh` кладёт симлинк `blueprint` в `~/.local/bin`, поэтому `git pull` в репозитории сразу обновляет и команду. Каталог `~/.local/bin` должен быть в `PATH`.

## Быстрый старт

```bash
cd ~/projects/my-app
blueprint init
blueprint
```

`init` кладёт в корень проекта `blueprint/` с кодом страницы и собирает конфиг под раскладку проекта. Он ищет готовую документацию (`docs/`, `documents/`, `wiki/` и подобные), схему `.excalidraw`, ADR, roadmap и идеи, затем спрашивает пути, подставив найденное:

```text
нашёл в проекте: documents/ (74 .md), documents/adr/
Enter оставляет предложенное, «нет» убирает пункт
Документация (папка) [documents]:
Исключить из документации [archive]:
Схема архитектуры (.excalidraw) [documents/architecture.excalidraw]:
Макеты экранов (папка) [нет]:
Roadmap (файл) [нет]:
Идеи (файл) [нет]:
ADR (папка) [documents/adr]:
```

В новом проекте предлагается эталонная раскладка: `docs/`, `docs/architecture.excalidraw`, `design/mockups/`, `docs/roadmap.md` и `IDEAS.md`. Заготовка макетов создаётся, только если папка макетов указана и её ещё нет. Без вопросов, например в скрипте или для агента, пути задаются флагами: `blueprint init --docs documents --exclude archive --mockups нет --yes`.

`blueprint` без аргументов поднимает сервер и печатает адрес, по умолчанию http://localhost:5190. Отсутствующие файлы страница не требует: схема создаётся при первом сохранении, ненайденный документ показывается пометкой.

Страница коммитится вместе с проектом, поэтому у того, у кого CLI нет, она запускается напрямую:

```bash
python3 blueprint/serve.py
```

## Команды

| Команда | Что делает |
|---|---|
| `blueprint init` | кладёт страницу в `./blueprint/` и собирает конфиг под раскладку проекта; существующий конфиг и каталог макетов не трогает |
| `blueprint init --reconfigure` | заново задаёт пути и пересобирает `blueprint.json` |
| `blueprint init --docs … --exclude … --architecture … --mockups … --roadmap … --ideas … --adr … --yes` | то же без вопросов; `нет` вместо пути убирает пункт |
| `blueprint update` | обновляет код страницы в проекте до версии из репозитория, конфиг и макеты не трогает |
| `blueprint` или `blueprint serve` | запускает сервер из корня проекта, ищет `blueprint/` вверх от текущей папки |
| `blueprint new-screen OrderDetail --title "Заказ" --about "…"` | создаёт файл экрана и запись в `screens.json`; `--group` и `--size 1280x800` необязательны |
| `blueprint check` | проверяет макеты и выводит проблемы с файлом и строкой; код возврата 1, если что-то нашлось |

## blueprint.json

```json
{
  "title": "Мой проект",
  "port": 5190,
  "tabs": [
    { "id": "architecture", "title": "Архитектура", "type": "excalidraw",
      "file": "docs/architecture.excalidraw", "docs": ["docs/stack.md"], "docs_label": "Стек" },
    { "id": "docs", "title": "Документация", "type": "docs", "dir": "docs", "exclude": ["archive"] },
    { "id": "adr", "title": "ADR", "type": "adr", "dir": "docs/adr" },
    { "id": "mockups", "title": "Макеты", "type": "frame", "src": "design/mockups/index.html" },
    { "id": "mvp", "title": "MVP", "type": "markdown",
      "docs": [{ "path": "docs/roadmap.md", "collapsed": false }, { "path": "IDEAS.md", "collapsed": true }] }
  ]
}
```

| Поле | Смысл |
|---|---|
| `title` | заголовок страницы и вкладки браузера |
| `port` | порт сервера, по умолчанию 5190 |
| `tabs[].id`, `tabs[].title` | якорь в адресе и подпись вкладки |
| `type: "excalidraw"` | `file` это схема, `docs` открываются кнопкой в шапке, `docs_label` её подпись (по умолчанию «Документы») |
| `type: "frame"` | `src` открывается во встроенном окне; в тёмной теме к нему применяется инверсия цветов |
| `type: "markdown"` | `docs` идут подряд на странице |
| `type: "docs"` | `dir` показывается деревом markdown-файлов, `exclude` перечисляет подпапки, которые не показывать; первым открывается `README.md` папки, адрес документа сохраняется в ссылке |
| `type: "adr"` | `dir` показывается списком решений: название из заголовка `#`, статус из строки «Статус:» или `status:` |
| элемент `docs` | строка с путём или `{ "path", "collapsed" }`: `true` свёрнутый блок, `false` раскрытый, без поля обычный документ |

Все пути считаются от корня проекта.

## Макеты

`design/mockups/` устроен так, чтобы нейронка правила один экран, не читая остальные:

```
design/mockups/
  wire.css        токены, утилиты и компоненты, общие для всех экранов
  wire.js         общие блоки (шапка сайта и телефона), data-repeat
  feedback.js     отзывы: точки на элементах, панель, сохранение в FEEDBACK.md
  FEEDBACK.md     отзывы по экранам, появляется после первого отзыва
  screens.json    подписи общих блоков и манифест: файл, название, группа, размер, описание
  index.html      доска
  <Экран>.html    один файл на экран, только разметка на классах
```

Нейронка открывает `screens.json`, находит экран по описанию и правит один файл в несколько килобайт. Повторяющиеся блоки записаны один раз с `data-repeat`, шапка вставляется из `wire.js`, цвета и радиусы живут переменными в `wire.css`, поэтому правка общего вида делается в одном месте. Полные правила формата в стандарте `mockups.md` репозитория my-dev-standards.

`blueprint check` проверяет то, что иначе держится на внимательности: каждый экран записан в `screens.json` и наоборот, все классы есть в `wire.css`, в `style` только размеры и позиция, а не цвета и отступы, блоки `data-wire` есть в `wire.js`, `data-repeat` больше единицы. Проверка без зависимостей и занимает доли секунды, поэтому её можно запускать после каждой правки.

Вместе с заготовкой в папку макетов ложится `AGENTS.md` на десяток строк: найти экран в манифесте, создать новый через `new-screen`, править классами, закончить, когда `check` чист. Так макеты уверенно правит и слабая модель: ей не нужно помнить стандарт целиком, ошибки она видит в выводе проверки и исправляет по подсказке. Чтобы агент нашёл эти правила, добавь в корневой `AGENTS.md` проекта строку со ссылкой на `design/mockups/AGENTS.md`.

На доске экраны вставлены прямо в страницу, без iframe, поэтому отзывы работают на всех экранах сразу. Отзыв хранит путь к элементу от `.screen` экрана, по нему точка встаёт на место после перезагрузки, а модель находит место в файле. Название над превью открывает экран отдельно на весь размер, отзывы работают и там.

## Безопасность

Сервер слушает только `127.0.0.1`. Список файлов для вкладок `docs` и `adr` он отдаёт только по папкам из конфига, без скрытых и исключённых каталогов и без выхода за пределы проекта. На диск сервер пишет ровно в одном случае: сохранение схемы из вкладки типа `excalidraw`, причём путь должен совпасть с `file` из конфига и лежать внутри проекта. Запрос на запись с чужим `Origin` отклоняется, файлы `.git*` и `.env*` не отдаются, всё уходит с `Cache-Control: no-store`, чтобы страница не показывала устаревшую версию файла.

## Как устроено

```
bin/blueprint        CLI: init, update, serve, new-screen, check
bin/mockups.py       проверка макетов и создание экрана
page/                код страницы, копируется в проект при init и update
  serve.py           сервер на http.server
  index.html         importmap с версиями React, Excalidraw, marked и mermaid
  blueprint.js       вкладки, схема, дерево документации, ADR, тема, скелетоны
  blueprint.css      оформление
template/            заготовка папки макетов с AGENTS.md для агента
install.sh           симлинк CLI в ~/.local/bin
```

Код страницы копируется в проект, а не подключается из глобальной установки: так страница работает у любого, кто склонировал проект, и не ломается, когда CLI обновился, а проект нет. `blueprint update` подтягивает новую версию осознанно, отдельным диффом.
